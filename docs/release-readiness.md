# Release Readiness

Audit date: 2026-10-09

DevDock has completed the implementation and verification gates in phases 0–7. The latest full native matrix passed at the 0.1.0 release commit `3d5c631` in [workflow 37879194878](https://github.com/Safeqq/devdock/actions/runs/37879194878), including build, typecheck, lint, unit, integration, installed-package lifecycle, reproducible packaging, artifact and fresh-repack verification, SBOM, license inventory, and browser tests on Windows Server 2025 x64, macOS 15 arm64, and Ubuntu 24.04 x64.

## Native matrix package evidence

- At `3d5c631`, all three runners and the local Windows rebuild produced the same CycloneDX SBOM (76 components, SHA-256 `4deca489740bd49948b4231af89de3cc9b2aae981749d1297654a29d96e47211`) and the same license inventory (SHA-256 `6cc4ba1b6af6073aa637796284ed8e76314f5f93409e14243efcb0fe4e9acd44`).
- Each runner's 0.1.0 tarball had 3,449 entries and passed its own two-pack and fresh-repack checks. The Windows runner produced 4,613,595 bytes with SHA-256 `9852d106929d2fdf750846f6f227713f8daa36a0abdfdbc752d6856223909fcd`, byte-identical to the local Windows release asset rebuilt from the clean `3d5c631` tree. macOS and Ubuntu produced identical 4,613,640-byte tarballs with SHA-256 `3bf3b9006abf2e3a44edc0741a1e4a733c272a096cbbe4ed7fbbc3a962fd0f3b`. Tarball bytes are reproducible within an OS family, not across families; the release asset is the Windows build.
- The local tarball previously had 3,536 entries, three more than a clean checkout: two stale TypeScript outputs in `packages/platform/dist` and `mime/CHANGELOG.md` from an outdated local install that disappeared after `npm ci`. Workspace builds now empty `dist` before compiling.
- Two timeouts in earlier matrix runs are explained by per-step timings at `7ea89ea`. On Ubuntu, Chrome's first launch took 22.0 s and its first context 8.4 s, which caused the configuration browser test to time out at `da548d3` (35 s limit) and `fb2fed1` (60 s limit). On Windows, extracting the packed tarball took 86.6 s against a 120 s per-command limit, compared with about 6 s on macOS and Ubuntu; `fb2fed1` exceeded that limit. The browser tests now share one browser launched and warmed in a setup hook with its own timeout, so the configuration test is back to its original 35 s budget, and the tarball install allows 240 s. At `3d5c631` the shared startup took 29.8 s on Ubuntu, but the first test page still took 11.5 s because warming a context does not warm page creation; the test body used about 16 s of its 35 s. Windows tarball extraction took 131.2 s, up from 86.6 s, so that 240 s limit should be watched. Both slow steps appear specific to those runners, because later Chrome launches on Ubuntu and local Windows installs are much faster; their underlying causes were not investigated further.

## Local package evidence

- `npm run package:local` rebuilt `artifacts/devdock-0.1.0.tgz` with Node.js 24.21.0 and npm 11.19.0.
- The 0.1.0 tarball is 4,613,595 bytes with an unpacked size of 21,988,028 bytes, contains 3,449 entries including `LICENSE`, and has SHA-256 `9852d106929d2fdf750846f6f227713f8daa36a0abdfdbc752d6856223909fcd`.
- `react` and `react-dom` are now development dependencies of `@devdock/web`. The daemon only serves the prebuilt `dist` files, so React, ReactDOM, and `scheduler` were bundled but never executed. Removing them took 85 entries and about 8.3 MB of unpacked files out of the package. Locally, installing the tarball into a clean prefix took 23.7–27.7 s, compared with 34–45 s before; these are a few samples on one machine, not a controlled benchmark.
- The package contains the root CLI, README, changelog, and the five required runtime workspaces: daemon, web, contracts, platform, and storage.
- Internal DevDock `src` and `tests` directories, root development configuration, repository scripts, CI configuration, artifacts, and local docs are excluded.
- `npm run check:versions` verifies that all six manifests, internal dependency pins, and workspace lockfile entries use the root version before either package command builds an artifact. A temporary `9.9.9` skew test failed with both source-manifest and lockfile diagnostics as intended.
- `npm run package:local` now creates two isolated npm pack results, audits both, and requires byte-for-byte equality before promoting the tarball. It then writes ignored `artifacts/package-latest.json` and `artifacts/devdock-0.1.0.tgz.sha256` after independently matching npm's SHA-1 and SHA-512 integrity. The schema 2 report records the two successful pack attempts, SHA-256, sizes, 3,449 entries, 73 bundled dependencies including all five DevDock workspaces, and the pinned runtime identity without absolute local paths.
- `npm run verify:artifact` independently checks an existing tarball, schema 2 report, reproducibility evidence, and checksum against the current manifest. Its unit test accepts intact fixture bytes, rejects an unproven reproducibility claim, and rejects a same-size artifact after one byte is changed.
- `npm run verify:reproducible` first verifies the promoted artifact, then creates one isolated fresh npm pack and requires an exact byte match. Its unit test accepts current package inputs and rejects the previously valid artifact after an included README changes. `release:inspect` and the strict candidate gate include this freshness check as `artifact-current`.
- `npm run package:sbom` generates a deterministic CycloneDX 1.5 document from the production-only package-lock tree. It normalizes npm's checkout-folder root identity, removes volatile timestamps, derives the UUID from semantic content, and records schema 2 evidence linking the SBOM to the lockfile and tarball. The 65,193-byte document has SHA-256 `4deca489740bd49948b4231af89de3cc9b2aae981749d1297654a29d96e47211`, 76 components, 77 dependency nodes including the root, and exactly the same 73 unique package names as npm's bundled package report. All 76 component references, versions, and package URLs match the production lockfile; five are linked workspaces and the other 71 also match their SHA-512 integrity and distribution URL. `verify:sbom` rejects development components, exact dependency drift, stale inputs, local paths, URL credentials, and sensitive query parameters; readiness includes it as `sbom-evidence`.
- `npm run package:licenses` derives `devdock-0.1.0.licenses.json` from that verified SBOM and links its evidence to both the SBOM hash and promoted tarball hash. All 71 third-party components, representing 68 unique package names, have declared license metadata across four unique SPDX identifiers: `BlueOak-1.0.0`, `BSD-3-Clause`, `ISC`, and `MIT`. The five linked DevDock workspaces are recorded separately with the project's MIT declaration. This is a factual metadata inventory, not a legal compatibility assessment.

- `npm run verify:package` passed on Windows native. Its latest clean-prefix package test completed in 23.0 seconds after the build, installed the tarball under a path with spaces and Unicode, exercised CLI flags without creating state, started the normal daemon, paired through the dashboard, and shut it down through the native adapter.

## Release decisions

The user selected these on 2026-10-09:

- Target: `repository`. The release is a Git tag and GitHub Release carrying the tarball, its checksum, the SBOM, and the license inventory. All six manifests stay `private: true`, so nothing is published to npm. The npm name `devdock` already belongs to an unrelated package, so any later npm target would need a scoped name.
- Version: `0.1.0`, applied with `npm run release:version -- 0.1.0 --date 2026-10-09 --write`. All six manifests, internal pins, lockfile workspace entries, README artifact names, and the changelog heading `0.1.0 - 2026-10-09` changed together.
- License: MIT. `LICENSE` is included in the tarball, and the root package plus all five workspaces declare `"license": "MIT"`. The root package also records repository, homepage, and issue-tracker metadata for `https://github.com/Safeqq/devdock`.
- The 3:20 demo recording is not part of this release.

`npm run verify:release` passed on the 0.1.0 tree, and `npm run verify:candidate -- --target repository` reported READY with every check passing.
